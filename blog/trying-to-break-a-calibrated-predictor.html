Trying to break a calibrated predictor

July 2025 | 6 min read

Take a predictor that says 50% to everyone. Half the cases come from A, where the event probability is 20%, and half from B, where it’s 80%. The overall probability is 50%, so the predictor is perfectly calibrated. It is also ignoring something we could use before seeing a single outcome: if the group is known when we make the prediction, we can give A a 20% prediction and B an 80% prediction instead. The calibration check accepts both versions, although one has thrown away information that would improve its predictions.

The definition makes room for this. Calibration requires E[Y∣P=p]=p. Here P is the predicted probability and Y is the binary outcome; among cases receiving a score p, the expected outcome must equal p. For the constant predictor there’s only one score, 0.5, and it checks out. Within A the prediction is 30 percentage points too high, and within B it’s 30 points too low, but averaging over the two groups removes both errors. Nothing in the condition requires that the same equality survive once we condition on the group as well.

Always predicting 50% makes the problem easy to see, but the cancellation doesn’t depend on having a constant prediction. Give the model three possible outputs, 20%, 50%, and 80%, and put equal numbers of A and B cases at each score. Set A’s event probability 15 percentage points below its score and B’s 15 points above. A then has probabilities 5%, 35%, and 65%, while B has 35%, 65%, and 95%. At every score p, the two probabilities p − 0.15 and p + 0.15 average to p. We now have a model whose predictions vary, with every combined point still sitting exactly on the diagonal.

A finer calibration plot won’t reveal anything new about the combined population. The two groups receive identical scores, so even a separate bin for every distinct prediction leaves their errors together. Recalibrating the output has the same limitation. A deterministic function that receives only the original score must return the same answer for A and B. In the constant example, it would have to map 0.5 to both 0.2 and 0.8; in the three-score example, it would need two different corrections at each score. A more flexible curve has no way to recover the group from an input that never distinguished it.

Once the correction can use the group, the three-score example is straightforward: subtract 0.15 for A and add 0.15 for B. We know the offsets because we chose the probabilities, which is a considerable convenience. Multicalibration, introduced by Hebert-Johnson, Kim, Reingold, and Rothblum, asks for approximate calibration across a specified collection of identifiable subpopulations. Those groups can overlap, and their rates have to be learned from data. Our two groups give a small example of the requirement, with the learning problem already solved for us. They don’t establish a guarantee for every subgroup we might decide to examine later.

The Python script makes this concrete with 1,000 rows per group–score pair, or 6,000 rows for the three-score example. A cell with an event probability of 5% gets 50 ones and 950 zeros. These are fixed counts, so there’s no sampling noise hiding the cancellation. Each row stores the group, prediction, event probability, and outcome, with Python’s Fraction type keeping the arithmetic exact:

for group, rate in (
    ("A", p - gap),
    ("B", p + gap),
):
    positives = 1000 * rate
    rows.extend(
        (group, p, rate,
         int(i < positives))
        for i in range(1000)
    )

For the pooled calibration error, the script buckets rows by prediction, averages the signed errors inside each bucket, then takes absolute values and weights them by each bucket’s share of the data. The grouped calculation does the same thing with separate buckets for each group and score. That changes where we take the absolute value: after A and B have cancelled in the pooled version, before they can cancel in the grouped version. The predictions and outcomes are identical in both calculations.

          pooled  grouped
constant  0.0000   0.3000
3 scores  0.0000   0.1500

The group information improves squared error too. The binary Brier score averages the squared distance between each prediction and its outcome, so lower values are better:

Brier=1n∑i=1n(pi−yi)2.

Predicting 50% for everyone gives a Brier score of 0.25, since both (0.5 − 0)² and (0.5 − 1)² equal one quarter. Using the known rates, 20% for A and 80% for B, lowers it to 0.16. In A that average is 0.2 × 0.8² + 0.8 × 0.2², and B gives the same result. For the three-score example, with equal counts in all six cells, using the true cell probabilities lowers the score from 0.19 to 0.1675. The improvement is 0.0225, exactly 0.15², because every original prediction was 0.15 away from its cell’s true probability.

More generally, when the event probability is q, the expected squared error at prediction p is q(1 − q) + (p − q)². Predicting q removes the second term; the remaining q(1 − q) comes from randomness in the outcome itself. This lets Brier distinguish two predictors whose pooled calibration errors are both zero. It also explains why a lower Brier score alone isn’t proof of better calibration: the score rewards separating high-probability cases from low-probability ones as well. The scikit-learn guide discusses that distinction in more detail.

All of this is unusually tidy because the probabilities are supplied and the outcome counts are fixed. Randomly sampling the same construction would make the observed rates fluctuate, and on real data we’d have to estimate those probabilities before testing the predictions on a separate sample. Searching for a group with a large error creates another problem: after enough attempts, we may find a group that looks bad simply because that particular sample was unusual. It needs a fresh sample before we can treat the gap as a repeatable failure.

Small groups make that harder. With 100 independent observations at an event probability of 50%, the sample rate has a standard deviation of 5 percentage points; with 10,000 observations, it’s 0.5 points. The same visible gap can mean very different things depending on the count behind it. Narrower score bins and more detailed groups leave fewer observations in each estimate, a tradeoff discussed by Arrieta-Ibarra and coauthors in their paper on calibration metrics. The exact zeros in this example let us isolate the cancellation, but they don’t tell us how precisely we could measure it in a dataset we hadn’t constructed ourselves.

There’s a consequence even before estimation enters the picture. Return to the constant 50% predictor and leave the event probabilities within A and B at 20% and 80%, but let B supply 80% of the cases instead of half. The overall probability becomes 0.2 × 0.2 + 0.8 × 0.8 = 0.68, putting the prediction 18 percentage points below the event rate. Neither group has changed internally; we just see more of B. The Brier score stays at 0.25 because a prediction of 0.5 has the same squared error for either outcome, even as pooled calibration fails.

The predictor using 20% for A and 80% for B remains calibrated under that change. It would also work if the proportions flipped the other way or almost every case came from B, as long as the rates within the groups stayed fixed. The constant predictor had needed A and B to arrive in just the right proportions for its errors to cancel. Changing those proportions is enough to break it.
